## 1. 共通ターゲット骨格

全画面を SL 層モックで確立した骨格に揃える（例外: QA モバイル）。

```
.app
├ .menubar（濃紺・右端 .menu-user）
├ .toolbar（フラット・主操作1〜2個 + seg フィルタ + .stat-strip）
└ .workspace（grid: 72px | 1fr | 288px | 58px）
   ├ .rail（左: 作業面切替 + ベル + .cn-card オーバーレイ）
   ├ .main > .main-card（中央: 画面の主役ビュー。.grid-frame / .tbl-frame で彫り込み）
   ├ .prop > .prop-card（右: 選択対象のプロパティ編集）
   └ .panel-rail（右端: 右パネルのモード切替）
```

画面別の「中央メイン」と「右プロパティ」の役割（design-refresh-plan §4.7 で確定）:

| 画面 | 中央メイン | 右プロパティ（panel-rail モード構成 = 2026-07-03 確定） |
| --- | --- | --- |
| SL 業務管理計画書 | SL 中央表（7列 + 変更履歴/備考列） | 現場詳細 / 社員配置 / 車両・ETC / 変更履歴（4モード） |
| OB 受注簿 | 受注行テーブル（`.dtable.dense` 基調）+ 行カレンダービュー（ツールバーで切替） | 詳細（選択連動: セル編集/行情報編集） / 連携・所在（請求先・現場住所・地図URL・SL/WS 連携状況） / 変更履歴（3モード） |
| WS 週間予定表 | 週単位の配置ボード（現場軸/社員軸） | 選択セル（配置編集+SL反映差分） / 社員 / 車両 / 協力業者・応援予約（4モード） |
| LA 休暇申請管理 | 月/週/年カレンダー（休暇・車両の2作業面） | ミニカレンダー（prop-card 上部常設）+ 詳細 / リスト / 要対応（3モード×作業面連動） |
| QA Quick Access | クイック入力カード（モバイル前提・共通骨格の例外） | **将来拡張**: 前回情報・単価・地図・不足項目（デスクトップ表示時のみ。R-3e では適用しない） |
| 経理（D・未着工） | 確認フロー + 請求行（方向性サンプル段階） | 差分根拠・承認・差戻し理由 |

**編集モデルの転換（2026-07-03 確定）**: 黒オーバーレイ中央モーダル編集 → 右プロパティ編集へ転換する。
転換は **R-3 の画面別適用と同時に一括実施**する（「同じ画面を二度触らない」計画原則）。
モーダルに残すのは 印刷プレビュー / ソート設定 / カラー設定 / 集計・CSV出力 / 一括操作 / 削除確認 のみ（D-01 規範）。

### 1.1 サブ機能の振り分け基準（SL 右プロパティ思想の一般化 / 2026-07-03 ユーザー確定）

各画面のサブ機能（フィルタ・詳細表示・履歴・設定・検索・一括操作・凡例など）は、**上から順に判定**して行き先を決める。
出発点は design-refresh-plan §4.3（SL の右プロパティ化対象 / モーダルに残すもの）で、これを全画面へ一般化した。

| 順 | 行き先 | 対象 |
| --- | --- | --- |
| 1 | **中央メイン** | 画面の主役ビューそのもの。行/セルへの直接操作（D&D・選択）。一覧性が業務価値になる状態表示（警告はアイコン集約、正常は主張しない） |
| 2 | **ツールバー** | 画面全体スコープの操作: 新規追加（主操作 1〜2個）・undo/redo・期間ナビ・ビュー/軸切替（ボタングループ A-04）・中央ビューを絞るフィルタ（seg C-01、組み合わせ選択は `data-multi`）・文字絞り込み（検索カプセル A-12）・統計サマリ（stat-strip B-05）・表示トグル |
| 3 | **右プロパティ**（prop-card + panel-rail） | 「選択中の 1 対象」の詳細確認・編集・履歴・差分・連携情報。D&D 供給源リスト（+リスト内検索・filter-btn 絞り込み）。既存の編集モーダル/ポップオーバーはここへ転換する |
| 4 | **モーダル**（D-01 用途限定） | 選択文脈から独立した設定・出力（印刷プレビュー / ソート設定 / カラー設定 / 集計・CSV出力）。複数対象への一括操作。削除確認などの危険操作（D-02） |

**横断ルール（同日確定）**:

- **フィルタ位置の統一** — 中央ビュー全体を絞るフィルタはツールバー常設 seg（GC 等の組み合わせは `data-multi`）、
  文字での絞り込みは検索カプセル。右プロパティ内のリスト絞り込みは filter-btn。
  OB のフィルタ行トグルと共通ナビの GC フィルタモーダルはツールバー seg へ吸収する
- **凡例の廃止（ヘルプ集約）** — 常設の凡例面は置かない。必要な画面はツールバー右端のヘルプ icon-btn
  （title / aria-label 必須）→ 濃紺ポップ/メニューで表示する。
  **実装済み（2026-07-11 / R-3f #7）**: OB/SL/WS/LA は共有ナビがツールバー右端へ画面別ヘルプを注入。QA はモバイルヘッダーへ専用ボタンを配置。LA 年間ビューに残っていた休暇人数・車検/点検の常設凡例もヘルプへ集約
- **対象外** — 通知センター / admin-notify は本振り分けの適用対象外（センターは side-nav+リスト+詳細の確立形で、
  詳細パネルが「選択対象の詳細」である点で思想整合済み。3カラム不採用判例を維持）

## 2. 共通適用手順（1画面 = 1サイクル = 1コミット）

1. **CSS 読替**: `co-tokens.css`（および旧 DS 依存の共通 CSS）を外し、
   `ds-tokens.css` → **`ds-legacy-aliases.css`（§3.3 正準エイリアス・必須）** → `ds-components.css` の順で読込。

2. **骨格再構成**: §1 の共通骨格へ再配置（menubar / toolbar / rail / main-card / prop / panel-rail）
3. **コンポーネント置換**: 画面固有 CSS を ds-components.css のクラスへ置換（§3 対応表）。
   置換しきれない画面固有スタイルは「ds のトークンのみ参照する画面 CSS」として残す（直書き hex 禁止）
4. **通知組込（R-2 成果物）**: ベル → `.cn-card` スライド表示、項目クリック → 該当セルへスクロール + `.is-selected` + `.cn-flash`

6. **Playwright 検証**: コンソールエラー0・1440px 基準・`screenshots/` へ保存。
   **加えて `node scripts/design-audit/ds-audit.js` が NG=0 であること**（未定義トークン参照はコンソールエラーを出さず
   目視でも見落とすため。経緯: R-3d の太字・意味色無効化、2026-07-10 横断レビューの OB/WS 同型欠落）→ コミット
