# SL モック デザインレビュー（DS 化前の批評）

- **日付**: 2026-06-11
- **レビュアー**: Claude Code (Fable 5)
- **対象**: `docs/preview/design-refresh-sl-layer-mockup.html`（HEAD 9df9cfb 時点）
- **目的**: 本モックをベーステンプレートとしてリファクタ用デザインシステム（DS）を抽出する前に、現状デザインの批評と改善点を文書化する
- **検証方法**: コード全読 + Playwright 実画面確認（1800x1000、メインカード / プロパティカード / バッジ / 変更履歴カード / ツールバーの部位別撮影）

## 1. ベースデザインの理解（デザイン言語の言語化）

このモックが育てているデザイン言語は **「白い成形素材のデスクトップワークスペース」**。

- **メタファー**: Photoshop 型の作業画面（暗色メニューバー + 左ダークレール + 中央ドキュメント + 右プロパティ + 右端モード切替）の上に、「乳白色の成形パネル」「彫り込まれたトレイ」「ピル型チップ」という物理素材の語彙を載せる。macOS Big Sur 以降 / Fluent 2 に近いソフトマテリアル系譜で、ネオモーフィズムほど彫りは深くない。
- **素材表現の文法**:
  1. ごく薄い斜めグラデで「面の起伏」
  2. border の方向別色（上左明・右下暗）で「面取りベベル」
  3. inset ハイライト / シャドウで「縁の厚み」
  4. 青灰色のドロップシャドウ（`rgba(38,73,99,…)`、黒でなく環境色）で「高さ」
- **高さ管理**: `--elevation-0〜5` のトークン階層。最上位は左レール。
- **凹凸の使い分け**: メインカード = `::before` の 6px トレイ（台座の上の板）/ `grid-frame` = inset 影の彫り込み井桁 / バッジ = 浮いた持てるチップ（D&D アフォーダンス）/ アクティブタブ = 押し込み。
- **色**: 青灰ベース（bg `#eef4f8` / ink `#172b3a`）に意味色を厳密分離 — 夜間 = Flexoki Red `#D14D41`（文字）、警告 = Signal Orange `#F15E2A`（アイコン・バッジ限定）、所属 = Flexoki 600 系 5 色（人物アイコンのみで担う）。装飾色を面で使わず、データの色だけに彩度を割く。
- **タイポ**: Inter + Noto Sans JP、`tabular-nums`、「数値 = 主役（人数 18px）/ 現場名 14px = 準 / ラベル・バッジ 11〜12px = 従」の 3 層。

方向性は業務システムとして筋が良い。「余白で間引かず、線と面の差で高密度を読みやすくする」という Calm Operations の方針と素材感の語彙が一致している。

## 2. 良い点

- 影が黒でなく青灰。環境光に馴染み、安っぽい浮きにならない。
- 意味色の分離設計（夜間赤 vs 警告橙、暖色をテーマから排除し警告色に独占させる）は色設計として正しい。
- elevation トークン化、`tabular-nums`、`::before` トレイの同心円角丸（14+6=20px）など細部の計算が効いている。
- 中央表の行高 72px / ヘッダ 32px の対比、セル縦中央揃えのリズム。

## 3. 課題

### 3.1 ★最重要: 光源が画面内で矛盾している

- **ベベルと影は「左上光源」**: border 上左白・右下暗（`.person` 等）、inset ハイライト上端白、ドロップシャドウは真下（`0 4px 9px`）。`grid-frame` のコメントも「光源(左上)」と明記。
- **面のグラデは「右下光源」**: `.main-card` は `to bottom right, #f4f7f9 → #ffffff`（左上暗 → 右下明）。ページ背景も右下にラジアル白。バッジ・検索・タブも同方向。

経緯: Codex 側が「右下から浅い拡散光」、Claude 側が「光源を左上に統一」と、2 つの AI が逆の光源で実装した履歴がそのまま共存している。現実の素材は「縁は左上から照らされ、面は右下から照らされる」状態になれないため、目は理屈抜きに CG っぽさを感じる。

**推奨**: 左上光源に統一（ドロップシャドウが下に落ちる以上こちらしか整合しない）。面グラデを反転し「左上 = 明 → 右下 = やや暗」へ。DS の第一条として「光源は左上固定。面は左上明、ベベルは上左白 / 右下暗、影は下方向」を明文化する。

### 3.2 角丸・形状

- 角丸の在庫が多すぎる: 4 / 5 / 6 / 7 / 8 / 9 / 10 / 11 / 13 / 14 / 20 / 999 が混在。`--radius: 8px` トークンはほぼ未使用。**4 / 8 / 14 / 20 / pill の 5 段**へ整理を推奨（チップ内要素 = 4、ボタン・小カード = 8、大カード = 14、トレイ = 20）。
- 同心円角丸の破れ: `grid-frame`(14px) の内側 6px パディングに対し `.grid` が 10px。同心に見せるには「内側 = 外側 − ギャップ」なので **8px が正解**。`::before` トレイ側（14+6=20）は正しい。

### 3.3 タイポグラフィ

- **ウェイトのインフレが最大の課題**。700〜900 がラベル・本文・ボタンほぼ全部に使われ（`--table-strong: 800`、section-title 900、detail dd 800 等）、「数値 = 主役」の階層を弱めている。Noto Sans JP の 11px×800 は Windows ClearType で潰れる。
- 推奨基準: **データ 500–600 / ラベル 600 / 見出し 700。800 以上は主役数値 1〜2 箇所のみに留保**。小ラベルの格は太さでなく「色（muted）+ letter-spacing 0.02–0.04em」で出す。
- フォント読込が 400–900 × 2 書体と重い。実装時は 3 ウェイト程度に絞る。
- `person-name` の `max-width: 42px` は 14px×3 文字ちょうどで、3 文字姓（佐々木・長谷川）が確実に省略される。56px 程度へ。
- 数値階層は現在「人数 18px > 時間 14px」（時間 14px はユーザー判断で確定済み）。配置担当者の最頻スキャン対象が集合時刻なら序列の再検証余地はあるが、変更は提案しない（観点の記録のみ）。

### 3.4 余白

- セルパディング `8px 13px`、gap 5/6/7/9/11px と奇数値が散在。知覚差がないため **4px ベース（4/8/12/16）+ 例外 6px** に量子化を推奨。
- 左端の整列線: メインヘッダ「業務管理計画書」（padding 14px）と表内 1 列目テキストの左端が揃っていない。タイトル・検索・表の左エッジを 1 本のガイドに乗せる。

### 3.5 色

- muted `#667786` のコントラストが境界線上: 白地 4.6:1（AA ぎりぎり）、淡青地 `#f1f6fa` 上で約 4.3:1（AA 落ち）。11px 多用のため `#5a6b7a` 程度へ半段暗くするのが安全。
- **変更履歴の濃紺カードが視覚階層の頂点を奪っている**。白基調で最も濃い面は無条件に最強の注意を引くが、現状は履歴があるだけで常時濃紺 = 平常情報が一番目立つ。**状態駆動**（未確認の変更がある行だけ濃紺、確認済みは淡色）にすると濃紺が「要注意」シグナルとして機能する。
- GC 色と所属色が同一パレットの同一色相（`--gc-touo: var(--belong-1)` 等）。円バッジ = GC、人物アイコン = 所属と形で分けてはいるが、同じ行に同色相が並ぶと誤読リスク。所属色選択 UI 側で GC 3 社が使う色相を除外する制約が有効。
- 夜間赤が行内の時間・名前・現場名すべてに乗ると「エラー行」に見えやすい。Excel 由来の慣習仕様と理解した上で、将来案として「時刻数値のみ赤 + 月アイコン」の縮退案を検証候補に記録。

### 3.6 影・素材表現

- `grid-frame` の彫り込みが事実上不可視（alpha 0.02〜0.014）。等倍では罫線と区別がつかず、コストだけ払う状態。**0.05–0.06 × blur 2–3px まで上げて「彫り」として成立させる / ヘアライン 1 本に簡素化する**の二択。
- 静止状態のバッジの影が多い（外影 2 層 + inset 2 層 × 行内多数）→「ステッカーシート」化。D&D アフォーダンスは cursor:grab と hover の浮き上がりで担えるため、**静止時は外影 1 層、hover/drag で 2 層**へ。
- 素材語彙が 1 画面に 5 種以上（台座トレイ / 彫り込み井桁 / 浮きチップ / 押し込みタブ / ダークガラスレール）。DS としては **Raised card / Inset well / Flat chip の 3 種程度**に公式語彙を絞る。
- `.category-badge` の `box-shadow: 0 2px 0`（ボケなしハードオフセット）は周囲の拡散影と文法が合わない。柔らかい影か削除へ。
- prop-card 内 `.section` が「カードの中のカード」で各自 border + グラデ + 影 + inset を持つ。**浮くのは prop-card 1 枚だけにし、section は淡い面色 + ヘアライン**へ。
- メイン = トレイ式 / プロパティ = 直貼りの構造差は直貼りへの統一が妥当（HANDOFF 記載の次タスク方針に賛成）。

## 4. DS 化に向けた提言

1. **光源宣言を DS の第一条に**。これが無いと担当者（AI 含む）ごとにブレ続ける。
2. **トークン整備の優先順**: 余白スケール → 角丸スケール → タイポロール（`--text-num-hero` / `--text-data` / `--text-label` 等）→ サーフェスレシピ。手書き box-shadow 群を `--surface-raised` / `--surface-inset` / `--bevel` 等の名前付きレシピに畳む。main-card::before と prop-card で意図的に同値にした影はトークン化すべきシグナル。
3. **濃色面の使用権を絞る**: ダークネイビーは「レール（ナビ）」と「未処理の変更」だけ、警告橙は「アイコン / バッジのみ・文字禁止」のように、色ごとの使用条件を文章ルール化する。

## 5. 総評

方向性と細部の研究量は本物で、白基調 × 素材感の業務 UI として既に水準が高い。残る課題は装飾の追加ではなく**矛盾の除去と語彙の圧縮** — 光源 1 本化、角丸 / 余白 / ウェイトの段数削減、影の知覚閾値管理。ここを締めれば「深みのあるスタイリッシュ」が安定して再現可能な DS になる。

### 光源ルールの公式例外（2026-06-11 ユーザー確定）

- **社員バッジ（`.person`）/ 車両・ETCバッジ（`.vehicle-tag`）の表面グラデ**は、青灰→白(60%)→青灰 の「中央が白く凹んで見える」表現を維持する。本デザイン最大の特徴部位のため、左上光源統一の対象から**恒久的に除外**（実装後に一度左上明へ反転したが、ユーザー判断で復元）。CSS 内にも例外コメントを明記済み。

※ 夜間赤の縮退・GC/所属色相分離・時間 14px は過去のユーザー判断を尊重し、今回スコープから除外（将来の検証候補として記録のみ）。
