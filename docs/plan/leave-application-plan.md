- Phase 2: モックアップ開発サイクル中

- 既存画面（SL/WS）とのUI整合性を重視（右サイドパネル・GCフィルタ等）
- アカウント管理画面（別モック、未着手）に「承認権限」「主承認者設定」「定期休マスタ」が絡む

## 2. 会話で確定した仕様（Q番号付き）

### 画面の役割と構造

| Q | 論点 | 決定 |
|---|------|------|
| Q1 | 画面の役割 | **ハイブリッド**（ロール判定で表示切替 / データソースは1つ） |
| Q2 | 表示スケール | **月間 / 週間 / 年間 の3ビュー切替**（上部タブ） |
| Q3 | WS連携方向 | **休暇画面が唯一の入力元**。WS側は読取専用バッジで表示 |
| Q4 | 社員バッジ配置 | **右サイドパネル・縦タブ折り畳み**（SL/WSと同一パターン） |
| Q16 | GCフィルタ | **SLと同一**（上部表示・バッジトグル・初期値保存・アカウント連携） |

### 休みの状態・種別

| Q | 論点 | 決定 |
|---|------|------|
| Q5 | 状態の粒度 | **全休 + 半休（午前/午後）のみ**を正式データ。時間帯制限はメモ欄フリーテキスト |
| Q7 | 全休の種別 | **有給 / 欠勤 / その他**（3種） |
| Q6 | 承認ワークフロー | **3ステータス**: 申請中 / 承認済 / 却下（却下時は理由コメント必須推奨） |
| Q15 | 繰り返しパターン | **詳細ポップオーバーに「毎週X曜繰り返し」オプション**（単発申請の拡張として） |
| Q14 | 過去日編集 | **過去日は管理者のみ編集可**。本人は未来日のみ申請/編集可 |

### 操作UI

| Q | 論点 | 決定 |
|---|------|------|
| Q8 | 詳細編集UI | **セル横ポップオーバー**（軽量）。区分/種別/メモ/繰り返し設定を1画面に |
| Q9 | 複数日入力 | **配置済みバッジの端をドラッグして期間延長**（Outlook/Google Calendar的操作） |
| Q17 | 月間ビュー情報密度 | **イニシャルバッジ + スクロール**。4件以上は「+N」で折り畳み、セルクリックで展開 |
| Q18 | D&D視覚フィードバック | **ゴースト + ドロップ対象セルハイライト + 週範囲プレビュー** |

### バッジ表示

| Q | 論点 | 決定 |
|---|------|------|
| Q10 | 社員バッジ情報（サイドパネル） | 氏名・GC色・役職 ＋ 有給残数・今月使用日数 ＋ 未申請/未承認アラート |
| Q11 | セル上のバッジ見せ方 | **氏名バッジ + 左上に区分アイコン（全/前/後）**。SLのバッジデザインと統一感 |
| Q12 | WS反映タイミング | **申請中も薄表示**。承認済=通常、申請中=破線枠 or 半透明 |
| Q13 | 衝突・集中警告 | ①既にWS配置済み社員の休暇申請時に赤アラート ②同日N人以上集中でセルに警告アイコン |

### 運用・権限

| Q | 論点 | 決定 |
|---|------|------|
| Q19 | 承認権限者 | **申請者の所属GCのDCPのみ承認可**（GC別権限） |
| Q20 | 通知 | **画面内通知のみ**（ヘッダー鈴アイコン + 未読カウント）。メール/外部通知は Phase 3以降 |
| Q21 | 月次集計・エクスポート | **月次集計モーダル + CSV出力**。有給消化/欠勤/欠有給/平均リードタイム等 |

### 月間ビュー（情報密度対策）

- 1セルに最大3名まで氏名バッジ、それ以上は「+N名」で折り畳み
- イニシャルモード時は氏名→「山」「佐」等の1〜2文字に圧縮（ホバーで氏名ツールチップ）
- 多人数集中時は警告アイコン（`im-11908-chuui-maaku.svg`）をセル右上に表示

### 週間ビュー

- 週単位のスワイムレーン（社員を縦軸、日付を横軸）
- WSと類似レイアウトで、休暇バッジのみ表示（配置情報は出さない）
- D&D連続日延長はこのビューが最も直感的

### 年間ビュー

- 12ヶ月のサムネイル（シンプルな日付マス + ヒートマップ）
- 各社員の年間有給消化状況ヒートマップ表示
- 月ヘッダークリックで月間ビューに遷移

## 4. 状態遷移とロール別挙動

### 休暇レコードのステータス

```
[申請中] ──承認──→ [承認済]
   │
   └──却下──→ [却下]（理由コメント必須）

[承認済] ──管理者が変更──→ [承認済(変更)]（履歴保持）
[承認済] ──管理者が取消──→ [取消](論理削除)
```

### ロール別の権限マトリクス

| 操作 | 本人 | 所属GCのDCP | 他GCのDCP | 経理等管理者 |
|------|------|------------|----------|-----------|
| 未来日の自分の休暇申請 | ○ | ○（代行） | × | ○ |
| 未来日の他人の休暇申請 | × | ○ | × | ○ |
| 申請中の承認/却下 | × | ○ | × | ○ |
| 承認済の変更 | × | ○ | × | ○ |
| 過去日の編集 | × | ○ | × | ○ |
| 月次集計CSV出力 | 自分のみ | ○ | × | ○ |

## 5. データモデル（mockup上の想定）

```js
// 休暇レコード
const leaveRecord = {
  id: 'lv-0001',
  employeeId: 'emp-101',
  date: '2026-04-15',           // 単日 or 連続日の各日
  partition: 'full',             // 'full' | 'am' | 'pm'
  kind: 'paid',                  // 'paid' | 'absent' | 'other'
  status: 'pending',             // 'pending' | 'approved' | 'rejected' | 'cancelled'
  reason: '私用',                 // 理由（却下時は却下理由で上書きされる可能性あり）
  memo: '14時以降出社不可',        // 時間帯制限等のメモ
  recurrence: null,              // または { rule: 'weekly', dayOfWeek: 3, until: '2026-06-30' }
  createdBy: 'emp-101',          // 申請者（本人 or 管理者代行）
  approvedBy: null,              // 承認者
  approvedAt: null,
  rejectedReason: null,
  history: []                    // 変更履歴（管理者が修正した場合）
};

// 社員マスタ（画面上での表示用、詳細はアカウント管理へ）
const employee = {
  id: 'emp-101',
  name: '山田太郎',
  gc: 'A',                       // グループ内会社
  role: 'staff',                 // 'dcp' | 'field-chief' | 'staff' | 'partner'
  paidLeaveRemaining: 10,        // 有給残日数
  paidLeaveUsedThisMonth: 2,     // 今月使用
  approvalManagerId: 'emp-050',  // 主承認者（アカウント管理で設定）
};

// アラート情報（サイドパネルの社員バッジに表示）
const alertInfo = {
  unsubmittedThisMonth: false,   // 今月未申請
  pendingApprovalCount: 1,       // 未承認件数（管理者視点では他人、本人視点では自分）
};
```

## 6. 実装フェーズ分け（提案）

### E1. 画面骨格と月間ビュー（最小動作）

- ヘッダー・GCフィルタ・月間カレンダー骨格
- 右サイドパネル（縦タブ折畳、社員バッジ表示）
- 社員バッジD&D → セルへ配置（全休固定、状態詳細なし）
- ダミーデータ20社員分で動作確認

### E2. ポップオーバー編集 + 区分/種別

- セル配置済みバッジのクリックでポップオーバー起動
- 区分（全/前/後）・種別（有給/欠勤/その他）・メモの編集
- ステータス3種の視覚表現（実線/破線/取消し線）

### E3. 連続日D&D（バッジ端ドラッグ）

- バッジホバー時に左右エッジにハンドル表示
- エッジドラッグで期間延長
- ドラッグ中の週範囲プレビュー

### E4. 週間ビュー + 衝突警告

- 週間ビューへの切替
- WS配置データとの衝突検知（赤アラート）
- 同日N人集中セルの警告アイコン

### E5. 年間ビュー + 集計モーダル

- 年間サムネイルビュー
- 月次集計モーダル（CSV出力）
- ヒートマップ表示

### E6. 承認ワークフロー + 権限切替

- ロール切替UI（モック用デモ）
- 承認/却下アクション
- 通知センター（ヘッダー鈴）

### E7. 繰り返しパターン + 過去日ロック

- ポップオーバーの繰り返し設定
- 過去日の編集制限（本人ロック、管理者のみ可）
- 月末締め処理（メモのみ、実装は後回し可）

## 7. 今後の論点（今回先送り事項）

- **主承認者マスタの設定**: アカウント管理画面で主承認者 + 代理承認者を登録する UI（Phase 3候補）
- **メール/外部通知**: LINE WORKS/Slack連携（Phase 3以降）
- **定期休マスタ**: パートタイマー等の「毎週水曜休」を社員マスタ側で保持する機構（繰り返し申請との使い分けを要検討）
- **月末締め処理**: 何日締めにするか、締め後ロック解除権限、経理への連携
- **出張・外出・研修等の「休みじゃないが不在」区分**: 現状は扱わない。必要になったら区分を拡張
- **代休付与ロジック**: 休日出勤→代休が発生する勤怠ロジック（経理連携で本格実装）
