## 所見

### DS準拠（デザインシステム整合）

D15-2 の本質である「WS `--cell-base-*` の DS エイリアス化」と「シフトヘッダの solid 化」が、いずれも Single Source of Truth を損なわない形で達成されている。特に評価すべきは以下の点:

- **WS 独自トークン名を温存しつつ DS 経由化**: `--cell-base-day` / `--cell-base-night` という WS 固有の参照名を維持したまま値だけ DS エイリアスに差し替える戦略は、23箇所に散在する既存参照を一切書き換えずに済み、差分ノイズと回帰リスクを最小化している。
- **shift-header のセマンティック明瞭化**: 旧 `linear-gradient(rgba(teal/rose, 0.08), ...) + var(--bg-surface-2)` は意図解読に時間がかかる実装だった。`var(--day-sat/sun)` solid 化により、「土日祝ヘッダは曜日色を直接使う」という意図が CSS 読解のみで把握可能に改善。
- **日付ヘッダの linear-gradient は意図的に温存**: TD が明示的にスコープ外とした `.md-ws-date-header.*` の rgba オーバーレイが忠実に残存しており、スコープ境界の判断が正確。

### カラーコーディネーション

Coastal Palette の色温度軸から見て、本フェーズの neutral 化は以下の点で正当化される:

- **WS と OB の色温度統一**: 両者とも勤務情報を扱う業務系画面でありながら WS のみ warm beige（`#F7F5F2`）だったのは、D15-1 以前から違和感を抱えた設計。neutral gray への統一により「業務系 = neutral、アクセントは曜日色で明示」という階層が明確化。
- **shift-header solid 化の彩度制御**: `#EAF0F1`（土）と `#F3ECEE`（日）は D15-1 で Coastal Palette 整合済の値。旧 linear-gradient は `rgba(teal 0.08) + bg-surface-2` で彩度が低かったが、新 solid は計算済みの薄い tint 値を直接使うため、色相の意図が視覚的にも明瞭。
- **text-primary on 新背景の余裕**: 9.21〜9.73:1 の高コントラストは、将来的に背景をさらに濃くする改訂余地（例: `--day-sat` を `#DDE8EA` 方向へ）を残しており、palette の進化可能性を損なわない。

### 機能回帰

意図的ビジュアル変化フェーズの宿命として「副作用で既存機能を壊していないか」が最大の懸念だが、以下の検証によりリスクはゼロと判断できる:

- Playwright Computed で 147 要素を走査し、未定義変数フォールバック（`rgba(0,0,0,0) + none`）が 0 件。
- Console エラー・警告 0 件（キャッシュバスト後）。
- `!important` を伴う selected 状態スタイル（行555〜610）も `var(--cell-base-*)` 参照のまま値解決のみ変わるため、selected 時の色合わせも論理的に整合。

### アクセシビリティ（text-tertiary の件を含む）

TD 指定項目はすべて AA を大幅クリアしており、本フェーズの a11y 品質は十分高い。ただし TE が追加観察として記録した `--text-tertiary (#5A8896)` の件は以下の通り整理する:

- **事実**: 新 neutral 背景上で 3.34〜3.57:1 と通常テキスト AA 4.5:1 未達（UI要素 3:1 はクリア）。
- **TDスコープ境界**: TD B4 / F1 / 重大Claim 1 は `shift-text-day/night` / `text-primary` のみを明示対象としており、`text-tertiary` は対象外。本フェーズは `text-tertiary` 値を変更していないため、**背景変化の副作用としての既存問題の顕在化**であり、本フェーズの責任範囲外。
- **背景の由来**: styles-light.css 行25 のコメントに「Phase D6.1: 旧 #6B9AA8（3.1:1 AA未達）→ 約4.6:1」とあるが、これは D6.1 時点の背景基準（推定 `#FFFFFF`）での値。Surface Tier 拡張（D15 系）で背景階層が増えたことで、D6.1 の前提が成り立たなくなった構造的問題。
- **採点判断**: TD スコープ外につき採点に直接反映させない（重大Claim 該当なし、F カテゴリ満点維持）。

### 保守性

- **コメント粒度**: `/* Phase D15-2: warm beige → neutral gray (DS 経由) */` と `/* Phase D15-2: linear-gradient → solid tint */` はいずれも「何を / なぜ」が 1 行で追跡可能。将来の読み手が blame + コメントで経緯を復元可能な記述レベル。
- **旧値のクリーン削除**: コメントアウトで保存せず物理削除した判断は、tokens.json v1.3.0（D15-1）と co-tokens.css がマスターである Single Source of Truth 原則に忠実。

### 残課題（別フェーズで対応）

1. **`text-tertiary` の AA 未達（本報告の追加観察）**
   - 現象: `--text-tertiary: #5A8896` が新 neutral 背景（`#F5F5F5` / `#F2F2F1` / `#EAF0F1` / `#F3ECEE`）上で 3.34〜3.57:1（通常テキスト AA 4.5:1 未達、UI要素 3:1 はクリア）。
   - 推奨対応: **D15-3 新設または D16 で対処**。候補案:
     - (a) `--text-tertiary` を濃色化（例: `#4D7887` 方向へシフトして ~4.6:1 確保）。Coastal Palette の濁色系に寄るため色相感は維持可能。
     - (b) WS / OB での `text-tertiary` 使用箇所を洗い出し、本文テキストとして使っている箇所は `--text-secondary` に置換、装飾系は据え置き（UI要素 3:1 は満たすため）。
     - (c) 新トークン `--text-tertiary-on-neutral` を新設して背景別に使い分け（複雑化するため優先度低）。
   - SC 推奨: まず (b) の使用箇所洗い出しで実害の大きさを定量化してから (a) / (b) の選択を決めるのが安全。
2. **WS 夜勤色の意味論整理（当初ロードマップ P4）**: `--shift-bg-night` / `--shift-text-night` の運用が「昼夜 tier」なのか「時間帯 tier」なのかの定義整備（design-refinement-plan.md §Phase P4 該当）。
3. **Shell Beige の DS 昇格（P5）**: 画面シェル（body 背景）に使われている beige トーンの DS トークン化。D15 で surface は整理されたが shell は未着手。
4. **`warning-text` 値の統一（P6）**: DS と各モックアップで `warning-text` の値が微妙に異なる件の統一。

### 運用ルール提案（D15-1 SC 申し送りからの継続）

- **「値同値の論理的ビジュアル不変」の governance テンプレート化**: D15-1 SC で提案した「値同値の場合は Computed 実測 + git diff で Before/After 画像差分を代替可」は、D15-2 でも TE が Computed 実測と git diff で機能回帰を担保しており実効性が確認できた。governance §5 に正式記載することを引き続き推奨。
- **text-tertiary のような「背景変化に伴う既存問題の顕在化」を検出するルーブリック追記**: F カテゴリに「本フェーズで変更していないが背景変化の影響を受けるテキスト色」の AA 再検算を任意項目として追加すると、スコープ外問題の早期発見に有効。
