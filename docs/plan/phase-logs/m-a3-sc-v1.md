## デザイナー視点コメント

### 1. font継承設計の堅牢性（◎）
OB の font-family は **body の 1箇所のみ** で `var(--font-family-body)` を指定し、子要素は `inherit` または意図的な `monospace` 1件のみ。これは「フォント統制は root で行い、子は継承のみ」という DS の原則に完全準拠しており、**色彩・タイポグラフィの一元管理**の観点から理想形。palt（プロポーショナル詰め）・tabular-nums（表数値の縦揃え）も body で効かせる設計で、テーブル密度が高い受注簿 UI において数値列の見た目が安定する。**この土台は M-B 以降のフォームCSSでも踏襲必須**。

### 2. M-A3 の委譲判断の妥当性（○）
案1（保守的）採用は正しい選択。font-size だけで実測 125件（行カウント）あり、DS 7段階に収まらない密度調整サイズ（7/8/9/10/12/12.5/15/18/19px）が**構造的に必要**なテーブル UI を、M-A3 単独で網羅置換するとリグレッションのリスクが高い。棚卸結果のまま M-C（テーブル密度）/ M-D（影・モーション）へ **責務分離** する判断は、INTJ 的戦略設計の観点からも合理的。

### 3. 棚卸件数精度の課題（△）
TD の集計が Grep 再実測と **約 +15 件** 乖離しているのは、TD 作成時点の ad-hoc カウントに起因すると思われる。後続フェーズ（特に M-C）で「置換候補 約82件」を見積もりベースに使うと、工数見積が過小になる恐れがある。**TE の推奨アクション（§3-1〜3-6）を TD に反映して v1.1 を出すことを強く推奨**。ただし M-A3 の合否自体には影響させない（実装変更ゼロのため）。

### 4. box-shadow の色混在問題（要注視）
TD §2-4 で `rgba(0,69,84,*)`（ブランドティール）と `rgba(0,0,0,*)`（汎用黒）の混在が明示されたのは優秀な発見。`--elevation-*` がブランド色ベースのため、**機械置換は見た目を変える**という洞察は妥当。M-D では「汎用黒の影は意図的か、それとも旧実装の残滓か」を**使用箇所単位**で判定する必要があり、単純な一括置換では対処できない。

### 5. monospace 1件の扱い（要判断・M-C候補）
body に `tabular-nums` が効いているため、タイムライン時刻表示の `monospace`（行1683）は**重複指定の可能性**がある。日本語フォント（Noto Sans JP 想定）の代用数字は tabular-nums 単独でも等幅化できるケースが多く、M-C で実機比較して削除可能か検証する価値あり。削除できればフォントスタックの一貫性がさらに向上する。

## Phase M-B への引き継ぎ（OBフォーム）

M-B（OBフォーム / モーダル内フォーム部）実装時に **厳守すべき事項**：

### 必須事項
1. **font-family は body 継承のまま**。フォーム要素（`input / select / textarea / button`）には `font-family: inherit;` を明示的に指定すること。ブラウザデフォルトの `Arial` / `Helvetica` 等への逆行（C3 相当）を防ぐ。
2. **palt / tabular-nums は body 継承を阻害しない**。フォーム要素に `font-variant-numeric: normal;` 等で打ち消さないこと。特に金額・日付・数量入力で tabular-nums が効いていることを実機確認。
3. **OB `:root` への font-* 追加禁止**。`--font-family-body` 等を OB 側で再定義しないこと（C4 相当）。フォーム用途の font-size は DS の `--fs-*` を優先、密度が必要な場合のみハードコードを許容（M-C 判断待ち）。

### 推奨事項
4. **font-size は DS 7段階を優先**。フォームラベルは `--fs-sm`(13px) / `--fs-caption`(11px)、入力値は `--fs-base`(14px) を基準にする。18px 等の大型入力は DS外として **M-C 判断**まで待つ。
5. **font-weight は DS 5段階内で収束**。400/500/600/700/800 以外の値（例: 650）を導入しないこと。
6. **line-height は `--lh-tight/normal/loose`（1.3/1.5/1.7）を優先**。1.2 / 1.4 の新規導入は M-C 承認が必要。
7. **フォーカスリングの box-shadow**（`0 0 0 2px var(--accent-primary-dim)` 等）は OB と同じパターンを踏襲。独自の色・幅で作らない。
8. **transition は 0.15s に揃える**。M-D で `--duration-fast`(120ms) と `--duration-base`(200ms) のどちらに統一するか決定するため、M-B では **`0.15s` ハードコード継続**でよい（越権しない）。

### M-C / M-D と重複しない範囲
- フォーム内でのみ必要な極小サイズ（例: ヘルプテキスト 10px）は **M-C の密度トークン**で扱う領域。M-B では棚卸まで、置換は待機。
- モーダルフォームの影（backdrop shadow 等）は **M-D の影統合**で扱う領域。M-B では OB 既存パターンを踏襲。

M-A3 は **実装変更ゼロのメタフェーズ**として設計された棚卸中心タスクで、その目的は達成されている。font継承の根幹（body での一元管理）は極めて堅牢に維持されており、M-B 以降のフォーム実装で同じパターンを**強制的に踏襲させる基盤**が整った。

**合格点: 90 / 100 → 合格**（重大Claim 0件、Phase M-B へ進行可）。
