# デザイン刷新 診断・比較計画

最終更新: 2026-06-03 / Codex (GPT-5)

## 0. 目的

社内レビューで出ている「少し古臭い」「画面のメリハリが弱い」「モッサリしている」という評価を、好みの議論で終わらせず、画面構造・密度・配色・部品ルールに分解して改善計画へ落とす。

本計画では、まず代表画面 3 種を診断し、次に代表 UI の 3 案比較で方向性を選ぶ。2026-06-01 時点では、案Bをベースにしつつ一覧性を落とさない **案B改: Calm Operations** を採用候補として具体化する。

## 2. 現行デザイン診断

### 2.1 総評

現行 UI は「機能は見えている」が、「重要度の差」が弱い。ナビバー、日付ヘッダー、ツールバー、左右パネル、表セル、チップ、件数表示が同じくらいの密度と色で並ぶため、視線誘導が平坦になっている。

古臭さの主因は、色そのものよりも、以下の複合:

- 濃いティールの帯が複数段に重なり、画面上部が重い
- 表の罫線が多く、セル境界が主役になっている
- 小さい文字が多く、情報の優先順位が見えにくい
- ボタンがほぼすべて同じアウトライン調で、主操作が分からない
- チップやバッジがすべて「枠付きの小箱」になり、画面全体が箱だらけに見える
- ピンク・水色・ベージュ系の薄い面色が多く、意味色と装飾色の区別が曖昧

|---|---:|---:|---:|---:|---|
| 業務管理計画書 | 798 | 392 | 217 | 234 | 左右パネルと表が同じ強さ。操作ボタンも同列で主従が弱い |
| 受注簿 | 1439 | 790 | 149 | 375 | 罫線密度が最大。日付セル全体が淡色で埋まり、数値の差が見えにくい |

### 2.3 画面別の主な課題

#### 業務管理計画書

- 左の配置状況、中央表、右の社員リストがすべて同じ濃度で、主画面が埋もれる
- ツールバーのボタンが横一列に並び、主要操作と補助操作の区別が弱い
- 点線ドロップゾーンが各行で目立ち、配置済みチップより空枠が主張している
- 不足・夜勤・休みなどの注意色が多く、警告の重みが分散している

#### 受注簿

- 罫線・日付列・固定列がすべて強く、Excel 感が前面に出ている
- 数字、薄い数字、下線、淡色背景が混在し、どこを見るべきか迷いやすい
- 上部のタイトル帯とナビ帯が近い濃色で重なり、画面冒頭が古い管理画面の印象になっている
- フィルタや表示切替が同じボタン強度で並び、探索操作と編集操作の差がない

#### 週間予定表

- スケジュール表、休み行、修理行、予約行、現場行がすべて線で区切られ、行グループのリズムが弱い
- 右サイドバーの社員チップが多く、中央の予定表と競合している
- 日付ヘッダー、昼夜ヘッダー、各セル枠が重なり、横方向の読み取りが重い
- ピンク系の注意色が広く散り、警告か装飾か判断しづらい

## 4. 採用候補: 案B改 Calm Operations

採用候補は **案B改: Calm Operations**。

案Bの「現代的で落ち着いた見た目」を採用しつつ、SL の中央メイン情報は現在の一覧性を維持する。余白を増やして情報量を削るのではなく、線・色面・編集導線を整理して、同じ情報量をより読みやすくする。

### 4.1 採用する4要素

| 要素 | 採用内容 | 目的 |
|---|---|---|
| 1. 中央表の一覧性維持 | SL の中央メイン表は、現在表示されている行・配置・不足・時間・人数が一覧できる状態を維持する | 現場運用で必要な俯瞰性を落とさない |
| 2. 右プロパティ編集 | セルクリック時の黒オーバーレイ中央モーダルを、右側パネルのプロパティ編集へ段階移行する | 編集中も中央表の文脈を失わない |
| 3. 右パネルのモード切替 | 右サイドを「社員」「車両」「応援」「予約」「選択セル編集」などのアイコン切替メニューにする | D&D 用リストと編集パネルを同じ場所で切り替える |
| 4. 検索の二層化 | 右サイド内検索に加え、中央メインメニューに「配置検索」を追加し、社員が現在どこに配置されているかを検索できるようにする | 右リスト検索と、中央表内の所在検索を分離する |

### 4.2 案Bそのままではなく B改にする理由

- 案Bそのままだと余白が増え、SL の一覧性が落ちる懸念がある
- SL は「表を見ながら編集する」画面なので、中央モーダルより右プロパティ編集のほうが文脈を保ちやすい
- 社員・車両・応援の D&D は右サイドを使い続ける必要があるため、右パネルは単なる編集領域ではなく、モード切替式の作業パネルにする必要がある
- 検索は「候補リストから探す」と「配置済みの所在を探す」で目的が異なるため、右サイド検索と中央配置検索を分けるほうが自然

### 4.3 右プロパティ編集へ移す対象

右プロパティ化に向いているもの:

- 行/現場セルの基本情報編集
- 集合・時間・人数・配置メモの編集
- 社員チップ、車両チップ、ETC、応援チップの詳細確認
- 選択中セルに関係する通知・履歴・差分の確認

モーダルを残すもの:

- 印刷プレビュー
- ソート設定
- カラー設定
- 複数行へ影響する一括操作
- 削除確認など危険操作

### 4.4 差分確認モック

`docs/preview/design-refresh-compare.html` に、以下の差分可視化を追加する。

- 現行: 中央モーダル編集で文脈が遮断される
- B改: 中央表は維持し、右パネルが「選択セルのプロパティ」に切り替わる
- 右端アイコンで「社員」「車両」「応援」「予約」「編集」を即切替
- 中央メイン上に配置検索を置き、社員名検索で配置済み行をハイライトする想定

### 4.5 B案寄りへ寄せる追加方針（2026-06-01）

初回の B改モックは中央一覧性を守る意識が強く、A案寄りの薄い業務グリッドに見えた。以後は以下を優先する。

- 画面全体はカード型ワークスペースとして構成する
- 右プロパティ編集は「サイドバーの一部」ではなく、独立した作業カードとして見せる
- 中央表は項目を削らず、表自体をカード内の高密度グリッドとして扱う
- 背景は白一色ではなく、薄い青系のレイヤーと柔らかい影で奥行きを出す
- 主操作は青系の塗りボタン、補助操作は淡い面ボタンに整理する
- 行ハイライトや検索結果は淡い面色で見せ、罫線ではなく面の差で認識させる

### 4.6 Photoshop型デスクトップUI方針（2026-06-01）

ユーザー案は有効。理由は、SL のような高密度操作画面では「上: 全体操作」「下: 作業面切替」を分離した方が、情報を削らずに操作対象を整理できるため。

- 上側はデスクトップアプリのメニューバー/ツールバーとして横並び固定にする
- その下の作業領域は、縦アイコンで「画面/作業面」と「右プロパティパネル」を切り替える
- 絵柄アイコンは `docs/assets/icons/` 配下の SVG を使う
- アイコンだけの操作は必ず tooltip / active state / aria-label を付ける
- SL 中央メインは列を削らず、まず高密度表示で「全情報を入れた状態」を確認する
- 文字サイズを詰める場合も、本文 11〜12px を下限目安にし、必要なら横スクロールを許容して情報欠落を避ける

注意点:

- Photoshop 型の左ツールバーは強力だが、業務画面では「道具の選択」より「作業面/パネル切替」として扱う方が迷いにくい
- アイコンだけに依存すると初見性が落ちるため、初期導入時はラベル付きツールチップまたは展開状態を用意する
- 右プロパティ化は有効だが、編集中の行/セルが中央で常に見えるハイライトが必須

### 4.7 他モックアップ画面への展開例（2026-06-01）

共通骨格:

- 左: 画面/作業面を切り替える縦アイコンレール
- 中央: その画面の主役となる高密度ビュー
- 右: 選択対象のプロパティ編集・検索・差分確認

### 4.8 SL 情報レイヤー方針（2026-06-02）

SL は、OB で営業担当が入力した受注情報を起点に、配置担当者が翌日以降の実行可能な社員指示へ確定していく画面として扱う。
通常は翌日分を配置するが、土日祝を挟むグループ会社では金曜日に土日月分をまとめて配置するなど、実運用上の配置対象期間は会社ごとに変わる。

この段階では、情報の発生源は OB であっても、翌日配置に関する最終判断の重心は配置担当者へ移っている。
SL 編集中に営業担当が OB を更新した場合、SL データ上は基本的に自動反映する。
ただし、その SL を操作中のアカウントの画面では、配置担当者が確認すべき「確認待ち」差分として見せる。
却下/差戻しは中央表で直接処理せず、変更通知側の操作として扱う。

#### 4.8.1 中央表の共通コア

中央表で常時見せる主情報は、配置担当者の判断と、将来の社員向け指示の両方に直結する情報に絞る。

| レイヤー | 情報 | デザイン上の扱い |
|---|---|---|
| L1 共通コア | 区分、契約先、現場名、集合時間、開始/終了時間、必要人数、配置社員 | 中央表の主情報として常時表示する。GCは行背景色とホバーで補助表示する |
| L1 状態 | 配置済み人数、不足/過多、配置注意、未連絡/連絡済み/再連絡必要 | 未達・注意・確認待ちを中心に表示し、正常状態のバッジは増やさない |
| L2 配置制約 | 区分適性、必要資格、資格者充足、社員同士のNG関係、連続勤務上限 | 通常は右プロパティへ置き、未充足時だけ中央表へ警告として出す |
| L2 配置判断 | 作業内容、備考、必要な技量、社員同士の組み合わせ、休み/重複/時間衝突 | 右プロパティの「配置判断」で詳しく確認する |
| L2 社員連絡 | 連絡方法、住所、地図、集合場所詳細、当日の注意事項 | 中央表には有無・未設定状態を出し、詳細は右プロパティに置く |
| L3 差分/権限 | OB更新あり、配置確認済み、営業へ確認中、再連絡必要 | 問題や状態変化がある時だけ強く表示する |
| L4 詳細/履歴 | OB連携元、変更履歴、通知履歴、内部メモ、請求・単価系 | 右プロパティまたは別画面へ寄せる |

SL 中央表の確認モックでは、列を `区分`、`契約先/現場名`、`集合`、`時間`、`人数`、`配置`、`車両/ETC` の7列に分ける。
区分は契約先/現場名セル内に混ぜず、左側の独立列に二行分程度の丸いブルー系バッジとして表示する。
集合と時間は別列に分け、車両とETCは同じD&D対象領域として1列にまとめる。
左メニューは濃色背景に白抜きSVGアイコン、中央表タイトルバーは青系グラデーションで、作業領域の現在位置を明確にする。
左メニューは単なるベタ塗りの縦帯にせず、外側の薄いフレーム、内側の濃色面、影、アクティブアイコンの半透明浮きカードで、枠内にメニュー面が嵌まっているようなマテリアル感を出す。
ツールバーはフラットな操作帯として維持し、同じマテリアル表現は外側の業務管理計画書パネル、中央表と右プロパティの間の縦型アイコンメニュー、右プロパティカードへ展開する。
色相は現在の青・青緑・白・薄い青灰を基準にし、新しい装飾色を増やさず、外枠、内面グラデーション、薄い内側ハイライト、多層シャドウで立体感を作る。
ドロップシャドウは高さレイヤーとして扱う。ツールバーは高さ0のフラット面、右パネル内セクション/通常ボタン、外側の業務管理計画書パネル、右プロパティカードは背景から少し浮く低い高さ、D&Dバッジは操作対象としてそれよりわずかに高く、左右の縦型アイコンメニューは最も高いレイヤーにする。
左メニューと中央右の縦型アイコンメニューは同じ列幅で扱い、左メニュー内の左右余白も均等にする。
中央表と右プロパティの間には右パネル切替用の縦型SVGアイコンメニューを置き、配置判断、社員連絡、履歴差分、車両、応援予約などを右プロパティ内で切り替える。
メインテーブルはカード枠の内側に情報枠を作り、外側のワークスペース枠とテーブル本体の境界を分ける。ただしテーブル本体の外枠は二重線にせず、情報枠側の一重線へ集約する。
列罫線は常時表示せず、セル内余白と横罫線で区切りを作る。集合、時間、人数はセル内で中央揃えにする。

#### 4.8.2 区分と配置可能社員

区分は小さなバッジに見えるが、配置可能な社員を決める制約情報なので、情報レイヤー上は上位に置く。

例:

- 施設警備: 施設課の社員を主候補にする
- 交通/高速: 交通課の社員を主候補にする
- イベント: 全社員を候補にする
- 応援交通: 交通課の社員を主候補にする

右側の社員候補リストは、選択中行の区分に応じて候補の並びや警告を変える。
不一致配置はブロックせず、単なる色違いではなく「区分適性に注意が必要な配置」として扱う。

#### 4.8.3 配置制約と候補リスト

配置制約は「警告で許可」を原則とする。
資格不足、社員同士のNG関係、連続勤務上限超過、区分不一致があっても配置操作自体は止めず、中央表は警告アイコン、右プロパティは理由付き警告で明示する。

資格要件は、通常時は右プロパティで必要資格名まで確認できるようにする。
多くの現場では資格者配置要件は「対象資格者が1名以上」で足りるため、通常 UI では人数条件を前面に出さない。
例外的な人数条件が必要な場合は将来拡張として扱う。

| 制約 | 表示方針 |
|---|---|
| 必要資格 | 通常は右プロパティで `施設2級 必須` / `交通2級 必須` のように資格名を表示 |
| 資格充足 | 対象資格者が配置済みなら中央表には出さず、0名なら警告アイコンを表示し、ホバーで `資格者不足` の理由を示す |
| NG関係 | 同一現場にNG関係の社員がいる場合、警告として表示 |
| 連続勤務 | 会社ごとの連続勤務上限（例: 12日以上）を超える場合、警告として表示 |
| 区分適性 | 施設/交通/高速/イベント/応援交通と社員所属課の不一致を警告表示 |

社員候補リストの基本並びは、`所属GC` → `区分/所属課` → `入社日の古い順` とする。
資格の有無や過去配置は基本並びに混ぜ込まず、右サイド上部の常時ボタンで素早く絞り込めるようにする。

| 候補操作 | 目的 |
|---|---|
| 資格絞り込み | 選択中現場の必要資格を持つ社員だけを素早く表示する |
| 過去配置絞り込み | 同じ契約先/現場への過去配置経験がある社員を素早く表示する |
| 基本並び | 会社・所属課・入社順の安定した順序で候補を読む |

#### 4.8.4 配置担当者向け情報と社員向け情報

SL 中央表は配置担当者の判断画面であり、社員向け情報をすべて同じ強さで表示する画面ではない。
ただし、社員へ伝える情報が不足していると最終アウトプットが成立しないため、中央表には「準備状態」として出す。

| 利用者 | 必要情報 | 表示方針 |
|---|---|---|
| 配置担当者 | 共通コア + 作業内容、備考、技量、組み合わせ、区分適性、休み/重複/時間衝突 | 中央表と右プロパティの「配置判断」で扱う |
| 社員 | 共通コア + 住所、地図、集合場所詳細、注意事項、連絡先 | 右プロパティの「社員連絡」で確認し、中央表には地図あり/なし・未連絡などの状態を出す |

右プロパティは「配置判断」「社員連絡」「履歴/差分」の切替を基本にし、中央表の一覧性を崩さず詳細確認と出力準備を担う。
連絡状態は `未連絡` / `連絡済み` / `再連絡必要` の3種類を基本とする。
SL 側で編集した内容は、すべて OB へ反映される。

## 5. デザインシステム・着せ替え構想

将来的に、同じ画面構造のまま Material / Neumorphism / Glassmorphism / Dense Ops などへ着せ替えできるよう、見た目をトークン化する。

### 5.1 分離するレイヤー

| レイヤー | 内容 | 例 |
|---|---|---|
| 構造 | 画面の情報配置・パネル構成 | 中央表 / 左状況 / 右作業パネル / 通知 |
| 部品 | UI コンポーネントの役割 | ボタン / チップ / 表 / 入力 / タブ / プロパティ欄 |
| トークン | 見た目の変数 | 色 / 角丸 / 影 / 余白 / 罫線 / 透明度 |
| テーマ | トークンのセット | Material / Neumo / Glass / Dense |

### 5.2 テーマ候補

| テーマ | 向いている用途 | 注意点 |
|---|---|---|
| Material | 標準的で分かりやすい業務 UI。影と面の階層が明確 | 独自性は控えめ |
| Neumorphism | 柔らかい印象、設定画面やカード型パネル | 表や小さいチップに多用すると視認性が落ちる |
| Glassmorphism | 右プロパティ、ダッシュボード、管理画面 | 背景とのコントラスト管理が必須 |
| Dense Ops | 現場向け高密度テーマ。表の一覧性・印刷互換重視 | 見た目の刷新感は弱め |

### 5.3 実装方針

- まず `design-tokens.css` 相当を作り、既存 CSS の直書き色を段階的にトークンへ置換する
- テーマは `data-theme="material"` のような属性で切り替える
- 画面構造・JS ロジックはテーマに依存させない
- 高密度業務画面では、テーマ切替後も行高・列数・表示情報量を保証する
- Neumorphism / Glassmorphism は全画面全面適用ではなく、右パネル・カード・通知など局所から試す

### 5.4 カラーコーディネート方針（2026-06-02 / 2026-06-04更新）

SL では、既存運用として夜間現場と夜間現場に配置された社員名を赤系文字で表してきた。
この慣習は視認上の意味が強いため、デザイン刷新後も残す。
ただし、デザイン刷新後の実色は画像参考に近い高彩度オレンジへ置き換え、夜間表示と警告表示は同じオレンジ系でも濃淡と背景で分離する。

色数は「ニュートラル + ブルー + オレンジアクセント」を基本にする。
GCや区分の種類ごとに別の色相を増やさず、同系色の濃淡、白文字/濃色文字、塗り/枠、背景濃淡で表現幅を作る。
フォントは画像参考の細身でモダンな数字表現に近い Google Fonts の `Inter` を主フォントとし、日本語表示は `Noto Sans JP` をフォールバックとして組み合わせる。

2026-06-04 追記: `Cyber Lime` など高彩度アクセントは子供っぽさが強く見えるため、現時点では採用候補から外す。添付画像のように、テーマごとに `BACKGROUND & TEXT` と `BRAND & BUTTONS` を分けた低彩度パレット群を先に完成させる。所属会社の選択カラーUIは下部に復活させ、画面全体のベーステーマとは別軸で比較する。UIは常時表示情報を会社名と小型スウォッチだけに絞り、色名/コードはホバー情報に逃がす。横1段には詰め込まず、2〜3段で余裕を持たせる。

## 6. 採用時のデザインルール案

### 6.1 色

- 濃色バーは原則 1 段まで。ページ内ヘッダーは白または薄いニュートラル面にする
- SLモックの白い素材面は、右下から浅い拡散光が入る前提で統一する。左上をやや締め、右下を白く抜く。検索カプセル、社員/車両/ETCバッジ、右プロパティカード、タブ、補助パネルも同じ `to bottom right` 方向の浅い面内グラデーションに寄せる
- 業務管理計画書テーブルのタイトルヘッダー、列ヘッダー、セル背景は白い素材表面として扱う。浮遊感、下方向の強いドロップシャドウ、暖色反射は使わず、タイトルヘッダーを含む業務管理計画書パネル全体を一枚板として左上がやや暗く右下が明るい、ごく浅い面内グラデーションにする。タイトルヘッダー/列ヘッダー/ボディセル単位では個別グラデーションを掛けず、外側に白いリム、その外周に薄い黒〜青灰の狭いグロー、パネル本体に弱い内側境界を入れて、低めの高さで左側縦型メニューバーに近い白い外枠の浮き上がりを出す
- 区分、契約先/現場名、配置などが並ぶ実テーブル外周は、外側へ浮かせず、内側の薄い青灰境界線と、そのすぐ内側の白いハイライトを重ねる内側段差リング方式で、少しへこんだ境界として見せる
- 主操作・現在位置・区分バッジはブルー系に統一する
- 社員・車両・ETCの所属会社色は、10社分を判別できる低〜中彩度の寒色〜紫灰系を採る。現行SLモックではカプセル型バッジの内側左端リブに留めて、名前や番号を主役にする。下辺の細い発光エッジ、外側フレア、中央一点の素材光は現行採用せず、判例CSSとして保存する
- 夜間現場は赤系文字で示し、警告とは背景/枠/アイコンで分離する
- 地図未設定やOB更新ありなどの情報差分は青系の枠線/薄い背景/文字で表示する
- 資格者不足、NG関係、連勤超過などの配置制約警告は、中央表ではオレンジ系アイコンに集約し、詳細はホバーで表示する。人数不足は人数セル下段のオレンジ系 `不足` バッジで表示する
- 正常状態は緑で主張せず、ニュートラルまたは非表示にする
- 背景は `#f7f9fb` 付近の薄いブルーグレーへ寄せる

### 6.2 罫線

- 表全体の罫線は 1px でも色を薄くする
- 縦方向の列罫線は原則使わず、列間の余白と整列で空間の区切りを作る
- 行グループの区切りだけ少し強くし、セル単位の境界は弱める
- ドロップゾーンの点線は常時表示ではなく、ドラッグ中またはホバー時に強調する

### 6.2.1 影

- 中央表本体の内側グリッドには影をかけず、外側の業務管理計画書パネルと右サイドメニューのプロパティカードは背景から少しだけ浮く程度の弱い影にする。配置社員バッジ、車両/ETCバッジはD&D対象としてそれより少し強い影にする
- 影は操作可能な部品や面の重なりを示すために使い、色数を増やす代替表現として扱う
- バッジのホバー時は影を少し強め、ドラッグ可能な対象であることを示す

### 6.3 文字

- 画面タイトル: 18〜20px / 700
- セクション見出し: 13〜14px / 700
- 中央表本文: 12px を基準にし、契約先/現場名、集合、開始/終了、配置名、車両、ETCは同じ表コンポーネント内の文字スケールとして統一する。開始/終了の間に区切り記号は置かず、縦位置で関係を示す
- 中央表の主要数値/時刻: 14〜16px / 800。時刻は `tabular-nums` で桁幅を揃える
- 補助情報: 11px まで。ただし多用しない
- 重要数値は色よりも太さ・配置・余白で強調する

### 6.4 ボタン

- 主操作は 1 画面 1〜2 個だけ塗りボタン
- 補助操作は薄いアウトラインまたはアイコンボタン
- 危険操作は常時強い塗りにせず、薄い背景 + オレンジ文字にして過剰な主張を避ける

### 6.5 チップ

- 社員/車両/応援/状態チップの形を整理する
- 通常チップは薄い背景 + 細い枠
- 警告は文章チップを複数並べず、アイコン + ホバーポップアップを基本にする
- 小さな枠付きチップを増やしすぎない。カテゴリは左端の小ラベルや列見出しで受ける
