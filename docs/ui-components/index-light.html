使用ルール

  • 余白・z-index・モーダル幅・フォントサイズ・Elevation・アイコンサイズ は必ずトークンを参照する。数値直書きは禁止。
  • トークンに存在しない値が必要な場合は、まず本セクションに追加してから使用する（自己判断で新しい値をハードコードしない）。
  • フォーカス可能な要素（input/button/a）は :focus-visible で box-shadow: var(--focus-ring) を適用する。
  • モーダルは var(--modal-w-*) のいずれかを使用。中間値は作らない。
  • 影は var(--elevation-*) を使用。旧 --shadow-sm/md/lg はエイリアス維持のみで新規使用非推奨（Phase D11 で deprecated 記載予定）。
  • カテゴリ色は --cat-bg-* / --cat-text-* のペアで使用。背景のみ適用すると可読性が落ちる。
  • アニメーション・トランジションは var(--duration-*) × var(--ease-*) の組み合わせのみ使用。prefers-reduced-motion は自動対応済。

data-density 属性で行高・行間・基準フォントサイズを一括切替。 下のデモ領域に属性を適用し、テーブル・ボタン・フォーム入力が連動して変化する様子を確認できる。

使用ルール

  • 密度切替は <html data-density="compact | comfortable | spacious"> で行う。任意の祖先要素への適用も可（子孫全体に伝播）。
  • 属性未指定時は comfortable 相当（:root 既定値）。
  • テーブルで明示的に .tbl--compact / --comfortable / --spacious を付けた場合は個別指定優先。data-density は「指定なし .tbl」にのみ伝播。
  • Button / Form は密度属性の祖先配下で自動的にパディング・フォントが調整される。独自 padding を上書きしない。
  • アカウント設定で選択した密度を localStorage 等で永続化し、アプリ起動時に document.documentElement.setAttribute('data-density', savedValue) で復元する運用を想定。

Print CSS（印刷スタイル）

Excel からの移行ユーザー向け帳票印刷要件に対応。 @media print で画面UIを隠し、表とコンテンツを A4 用紙に最適化。白黒トナー節約と識別性の両立。

既定: A4 縦 / マージン 15mm 10mm（初頁のみ上 20mm） / フォント 10pt / テーブル 9pt。 body.print-landscape を付与すると A4 横に切替。

ページ設定（@page）

@page（既定） A4 portrait margin: 15mm 10mm、初頁のみ上 20mm
body.print-landscape A4 landscape 横向き（受注簿一覧等のワイドテーブル用）margin: 10mm 15mm

ユーティリティクラス

.no-print 印刷時のみ非表示（画面では通常表示）
.print-only 画面では非表示、印刷時のみ表示（社判・備考欄など）
.print-only-inline 上記のインライン版
.page-break / .page-break-before その要素の前で強制改ページ
.page-break-after その要素の後で強制改ページ
.avoid-break / .page-break-avoid 途中での改ページを抑制（カード・承認印欄など）
.print-include 通常は印刷時に隠されるボタンを例外的に表示
.no-print-url リンクの URL 自動表示（a[href]::after）を抑制

自動で適用される印刷最適化

  • サイドバー（.sidebar）、アプリバー（.appbar）、ツールバー（.toolbar）、すべての <button> / .btn を非表示（.print-include を除く）。
  • メインエリア（.main）はマージン解除してページ幅いっぱいに展開。
  • テーブルヘッダ（.tbl thead）は display: table-header-group で継続ページにも自動表示。行（tr）は途中で切れない。
  • sticky ヘッダ・左端列固定は position: static に戻る（印刷では意味がないため）。
  • 集計行（.tbl-row--total）は上罫線 2px + 背景 #DDD で視認性強化。
  • 見出し（h1〜h6）の直後に改ページされない（page-break-after: avoid）。
  • 段落の孤立行は最低 3 行（orphans: 3 / widows: 3、Chrome/Edge のみ）。
  • 外部リンク（http/https/mailto/tel）は URL が自動で括弧付き表示。内部リンク（#）や javascript: は対象外。
  • フォーム要素（input/select/textarea）は枠線を下線のみに簡素化。
  • バッジ・チップ類は背景色を消し、枠線のみで識別（色に依存しない）。
  • 全要素の color: #000 / background: transparent / box-shadow: none を強制（トナー節約）。

使用ルール

  • 帳票印刷前提の画面（受注簿・請求書・業務計画書）は、必ず Chrome の印刷プレビューで A4 縦・横の両方を検証してから本番化する。

  • 途中で切れて欲しくないブロック（承認印欄・小計ブロック）は .avoid-break を必ず付与。
  • 印刷時の色は白黒最適化済み。グレースケール印刷で情報が失われないよう、バッジは枠線のみで識別。
  • A3 / B4 / レター等の他用紙に対応する必要が出た場合は、本 Phase を拡張して @page バリアントを追加する（自己判断で追加しない）。

Microcopy Guide（文言ガイド・Voice & Tone）

UI 文言のトーン・敬語レベル・動詞の使い分け・エラー文定型を統一する。

D10.1 敬語レベル

既定 丁寧語「〜します」「〜してください」 全UI文言の基本
エラー 状態描写 +（対処） 「保存できませんでした。再度お試しください」
確認 疑問形「〜しますか？」 「この受注を削除しますか？」

D10.2 動詞の使い分け

保存 既存データの更新 ↔ 破棄 編集画面・設定画面
登録 新規データの作成 ↔ 取消 新規作成モーダル
送信 サーバーへ反映 ↔ キャンセル 申請・問い合わせ等
更新 データ再取得 — 一覧のリロード
削除 データ消去 ↔ 復元 破壊的操作（必ず確認ダイアログ）

D10.3 エラーメッセージ定型

  • 原因 → 対処 の順で記述。「{何が起きたか}。{何をすればよいか}」
  • 否定形より肯定形を優先。✗「空欄にできません」 → ✓「値を入力してください」
  • 主語は省略可、目的語は明示。「保存できませんでした」→「受注情報を保存できませんでした」
  • 専門用語は避け、ユーザー視点の表現を使う。「バリデーションエラー」→「入力内容に誤りがあります」

D10.4 空状態のトーン

業務系（既定） 「データがありません」／「該当する受注はありません」
初回体験 「まだデータが登録されていません。[登録する]から開始できます」

Modal Design Pattern（確定仕様）

1. CSS命名規則

modal-* プレフィックスに統一（ob-modal-* は廃止）。画面固有でない共通パターンとしてシンプルな命名を採用。

要素クラス名説明
オーバーレイ.modal-overlay背景暗転レイヤー
コンテナ.modalモーダル本体
ヘッダー.modal-headerタイトル＋閉じるボタン
ボディ.modal-bodyスクロール可能な内容領域
フッター.modal-footerアクションボタン領域
閉じるボタン.modal-close✕ボタン（ヘッダー右上）
セクション区切り.modal-section-barテキスト＋横線の区切り
カード.modal-body-card白背景のグループ化カード
フィールド見出し.modal-body-fieldUsage Map風フィールド見出し
配置先タブ.ob-placement-tabsマルチサイト配置先のタブ切り替え
業務名表示.ob-cal-display-value読み取り専用の業務名表示（下線付き）

2. サイズバリアント（4段階）

バリアントクラス幅用途例
sm.modal-sm380px行編集、ソート、打合せ、作業時間、備考、地図
md.modal（デフォルト）480pxセル編集
lg.modal-lg520px現場詳細、カレンダー入力、変更通知
xl.modal-xl600px+将来の大型モーダル用

全サイズ共通: max-height: 85vh、max-width: 95vw

3. ヘッダー（全モーダル統一）

モーダルタイトル

  • 背景: #5AB8C6（var(--accent-light)）
  • タイトル: font-size: var(--fs-sm); color: #FFFFFF（font-weight は継承、明示不要）
  • 閉じるボタン: rgba(255,255,255,0.8) → hover: rgba(255,255,255,0.2) 背景
  • パディング: 14px 24px
  • 角丸: 上部のみ border-radius: 12px 12px 0 0
  • 夜勤対応: ヘッダー内のメタ情報（現場名・バッジ等）は夜勤行でも白系にオーバーライド

4. ボディ背景（2パターン）

A) カード型（情報量多いモーダル向き）

セクション名

白カード内にフォーム要素を配置

用途: 現場詳細、カレンダー+セル編集、打合せ、行編集、送迎・備考、地図、作業時間

B) フラット型（シンプルなモーダル向き）

bg-surface背景に直接フォーム要素を配置

用途: ソート、変更通知等の特殊レイアウト

5. フッター配置パターン（4種）

パターンレイアウト用途
A) 削除あり型[Delete] ─── [Cancel] [Save]現場詳細、カレンダー
B) 基本型─────── [Cancel] [Save]打合せ、作業時間、備考等
C) 閉じるのみ型─────── [Close]変更通知（読み取り専用）
D) フッターなしヘッダーの✕ボタンのみポップアップ、インライン編集
  • 背景: var(--bg-surface-2)
  • 配置: display: flex; justify-content: space-between
  • パディング: 14px 24px
  • 上部境界線: 1px solid var(--divider)

6. オーバーレイ

  • 背景色: rgba(0, 69, 84, 0.35)（アクセント色ベース）
  • 配置: position: fixed; inset: 0; z-index: 1000
  • センタリング: display: flex; align-items: center; justify-content: center
  • クリックで閉じる（モーダル本体へのクリックは伝播停止）

7. 開閉アニメーション（Fade + Scale）

対象開くduration
オーバーレイopacity: 0 → 10.2s ease
モーダル本体scale(0.95) → scale(1) + opacity: 0 → 10.2s ease
