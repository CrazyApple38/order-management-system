# 受注管理システム 要件定義書

## 1. プロジェクト概要

### 1.1 システム名
受注管理システム (Order Management System)

### 1.2 目的
現在Excel（VBA）で運用している受注簿・業務管理計画書をWebシステム化し、
データの一元管理、検索性向上、複数契約先の統合管理を実現する。

### 1.3 開発方針

- **Phase 1（先行開発）**: React + Node.js によるWebアプリケーションとして受注管理システムを構築
- **Phase 2（後続開発）**: 警備業法対応の教育記録管理システム、見積書・契約書作成機能等を開発し、本システムと連結
- 将来的にGoogle API・LINE API・会計ソフト等との外部連携を拡張する可能性がある

### 1.4 技術スタック

| 項目 | 技術 | 備考 |
| ---- | ---- | ---- |
| フロントエンド | Next.js (React) | **先行開発（プライマリUI）** |
| バックエンド | Supabase (PostgreSQL + Auth + Storage) | |
| 認証 | Supabase Auth (メール・パスワード) | |
| 外部連携 | Googleカレンダー API | |
| 既存データインポート | Excelファイル読み込み | 既存の受注簿・計画書データの移行用 |
| ホスティング | 未定 (Vercel推奨) | |

## 2. システム要件

### 2.1 利用者

- **対象**: 社内管理者（営業担当者・配置担当者・経理）
- **同時利用者数**: 少人数（1〜数名）

#### 2.1.1 ユーザーロール

| ロール | 主な業務 | 主な利用端末 | 主な画面 |
|--------|----------|-------------|---------|
| 営業担当者 | 契約先からの受注を受け、受注簿に入力 | モバイル（主）、PC | Quick Access、受注簿 |
| 配置担当者 | 受注に対して社員を配置し、日々の業務計画を作成。営業担当の代理入力も行う | PC（主） | 業務管理計画書、受注簿 |
| 経理 | 電票との付き合わせ、グループ間請求の確認 | PC | 経理画面 |

#### 2.1.2 業務フロー概要

```text
契約先 → [電話] → 営業担当者 → [受注簿に入力（Quick Access）]
    ↓
配置担当者 → [社員を配置（業務管理計画書）] → [社員へ通知]
    ↓
社員 → [現場で業務] → [電票にサイン取得]
    ↓
経理 → [電票と受注簿の照合] → [グループ間請求の確認・処理]
```

### 2.2 動作環境
- **PC**: Chrome, Edge, Firefox（最新版）
- **モバイル**: レスポンシブ対応（iOS Safari, Android Chrome）

### 2.3 既存システムとの関係

- **Webアプリ**: 受注簿・業務管理計画書の全機能をReact + Next.jsで開発
- **既存データ移行**: 既存のExcel受注簿・計画書のデータをインポートしてシステムに移行
- **データ連携**: 受注簿と業務管理計画書は同一DBを共有し、リアルタイム自動同期
- **後続開発**: 教育記録管理システム、見積書・契約書作成機能を開発し本システムと連結

## 3. 機能要件

### 3.1 受注簿管理

#### 3.1.1 データ項目
| カテゴリ | 項目例 |
|----------|--------|
| 契約先情報 | 契約先名、現場名、住所、連絡先 |
| 人員配置 | 配置人数、勤務時間、シフトパターン |
| 金額情報 | 単価、請求額、支払条件 |
| ステータス | 受注状況、変更履歴 |

#### 3.1.2 信頼度（受注確度）

受注データの確度を3段階で管理し、合計表示に反映する。

| 信頼度 | 説明 | グリッド表示 |
|--------|------|-------------|
| 確定 | 確定した受注 | 通常表示（不透明度100%） |
| 予定（信頼:高） | 高確率の予定 | 文字色を薄く表示（不透明度50%） |
| 予定（信頼:低） | 低確率の予定 | 文字色をさらに薄く表示（不透明度25%） |

**自動確定ルール**:

| ルール | 条件 | 動作 |
|--------|------|------|
| 過去日付ルール | 受注対象日が昨日以前 | 自動的に「確定」に変更 |
| 配置確定ルール | 業務管理計画書で社員が配置された | 自動的に「確定」に変更 |

**合計表示（最小～最大）**:

行合計・日別合計・総合計を「最小値～最大値」形式で表示する。

| 値 | 算出方法 |
|----|----------|
| 最小値 | 信頼度が「確定」のデータのみ合計 |
| 最大値 | 全データ（予定含む）の合計 |

※ 最小値と最大値が同じ場合は単一の数値で表示

#### 3.1.3 行情報編集

受注簿グリッドの固定列（会社・区分・昼夜・契約先名・業務名）をクリックすると行情報編集モーダルが開く。

| 項目 | 操作方法 |
|------|----------|
| 会社 | チップ選択（単一選択） |
| 区分 | チップ選択（単一選択）＋ 新規区分追加ボタン |
| 昼夜 | チップ選択（単一選択） |
| 契約先名 | テキスト入力 |
| 業務名 | テキスト入力（空欄で個別業務） |

※ 区分の新規追加時は、バッジ定義にも自動的に同期される

#### 3.1.4 バッジ（3階層）

作業内容モーダル・現場詳細入力モーダル・新規追加モーダルで、区分に紐づくバッジを3階層で選択できる。

**構造**:

| 要素 | 説明 |
|------|------|
| 親バッジ | 区分名をそのまま表示（読み取り専用） |
| 子バッジ | 区分ごとに定義されたバッジ候補（複数選択可） |
| 孫バッジ | 子バッジごとの詳細項目（複数選択可） |

**初期データ**:

| 区分 | 子バッジ | 孫バッジ例 |
|------|----------|-----------|
| 高速 | 車線規制、路肩規制、ブース規制、保安員 | 車線規制→標識車、規制材、保安灯 |
| 交通 | 片側交互、通行止め | 片側交互→旗、看板 |
| 施設 | （なし、追加可能） | — |
| イベント | （なし、追加可能） | — |
| 応援交通 | （なし、追加可能） | — |

**操作**:

| 操作 | 説明 |
|------|------|
| 子バッジ選択 | チップをクリックしてON/OFF切替（複数選択可） |
| 孫バッジ選択 | 子バッジ選択時に詳細パネルが展開され、孫バッジを選択可能 |
| バッジ追加 | 「+ 作業内容追加」「+ 追加」ボタンで子・孫バッジを新規追加 |
| 並び替え | ドラッグ&ドロップで子バッジ・孫バッジの表示順を変更 |
| バッジ削除 | ✕ボタンで削除。5秒間のUndoバー表示で復元可能 |
| グリッド表示 | セル内に選択済みバッジを 子バッジ › 孫バッジ 形式で表示 |

※ 親バッジ（区分）は行情報編集モーダルの区分変更に連動して自動決定される
※ 区分変更時、子バッジ選択はリセットされる
※ 作業内容モーダルと現場詳細入力モーダルの両方でバッジ選択が可能（独立したUI要素として動作）
※ DB上では `daily_site_orders.badge_child_ids UUID[]` に選択済み子バッジID、`badge_gc_map JSONB` に孫バッジ選択を保存

#### 3.1.6 祝日ハイライト

受注簿グリッドの日付列で土日・祝日に背景色を適用する。ツールバーのトグルボタンでON/OFF可能。

| 種別 | 背景色 |
|------|--------|
| 土曜日 | 薄い青系 |
| 日曜日 | 薄い赤系 |
| 祝日 | 薄い金色系 |

※ 祝日データは `holidays` テーブルで管理
※ ヘッダー行はデータ行より濃い色で表示

#### 3.1.7 夜勤行の表示

受注簿・業務管理計画書で夜勤データを視覚的に区別する。

| 画面 | 表示方法 |
|------|----------|
| 受注簿（月間グリッド） | セル内文字色を赤系（#DB577B）に変更 |
| 業務管理計画書（日次） | 行背景は白のまま、契約先名・現場名・集合時間・業務時間・人数・配置社員名の文字色を赤色（#DB577B）に変更。監督バッジ・集合列の連絡バッジも赤系統に変更 |

※ 2画面で異なるスタイルを使用する理由: 受注簿はセル単位で密度が高いため文字色で区別、業務管理計画書は行単位で主要項目の文字色を赤にして区別

#### 3.1.8 区分デフォルトラベル

セル編集モーダルの「業務詳細」で、区分に応じたデフォルトのラベル名を自動設定する。

| 区分 | デフォルトラベル |
|------|----------------|
| 高速 | 工事名、作業内容 |
| 交通 | 作業内容 |
| 施設 | 業務内容 |

※ ラベルはデフォルト値として使用。ユーザーが自由に変更可能
※ DB上は `site_sub_items.label` で管理（マスタレベル）、`daily_order_sub_items.label` で日毎にカスタマイズ可能

#### 3.1.9 複数配置先（マルチサイト）

同一行（同一契約先・同一業務）の同日セル内で、複数の配置場所に人員を分けて受注できる機能。

**ユースケース**: 同一契約先から同日に合計5名の受注があり、現場Aに3名・現場Bに2名のように、集合場所や時間が異なる複数の物理的な現場に分かれるケース。

| 項目 | 説明 |
|------|------|
| 配置先の独立性 | 各配置先は全項目が独立（人数・時間・監督・集合場所・バッジ・備考等） |
| グリッド表示 | セル内に各配置先の人数を縦並びで表示。それぞれ個別にクリック可能 |
| 配置先の追加 | セル編集モーダル内の「+ 配置先を追加」ボタンで新規配置先を作成 |
| 配置先の切替 | モーダル内の◀▶ナビゲーションで配置先を切り替え |
| 配置先の削除 | 「この配置先を削除」ボタンで個別に削除可能 |
| 合計計算 | 行合計・日別合計は全配置先の人数を合算 |
| ツールチップ | 複数配置先の場合、各配置先の情報を区別して表示 |

※ DB上は `daily_site_orders` の `placement_seq`（配置先連番）で同一日・同一現場・同一シフト内の複数配置先を区別

#### 3.1.10 カレンダー入力モーダル

受注簿グリッドの各行にあるカレンダーアイコンから、その行の月間カレンダービューを開いて編集する機能。月単位でセルデータを俯瞰しながら個別セルを編集できる。

**画面構成**:

| エリア | 内容 |
|--------|------|
| ヘッダー | タイトル「カレンダー入力」、月ナビゲーション（◀▶）、閉じるボタン |
| インフォバー | 会社略称チップ、区分\|シフトタグ、契約先名（小文字）＋業務名（太字）の2行表示、Undo/Redoボタン、バッジ表示トグル。薄いグレー背景でヘッダーとカレンダーグリッドの間に配置 |
| カレンダーグリッド | 月間カレンダー。各セルに人数バッジを表示。バッジ表示ON時は子バッジ名も表示 |
| 編集アコーディオン | セルクリックで展開。セル編集モーダルと同じフォーム（人数・信頼度・業務詳細・時間・監督・集合・地図・備考）を表示 |
| フッター | 削除・カレンダー表示・保存ボタン |

**操作**:

| 操作 | 動作 |
|------|------|
| セルクリック | 編集アコーディオンを展開し、該当セルのデータを読み込み。カレンダーは選択した週のみ表示に切替 |
| 別セルクリック | 現在の編集内容を自動保存し、新しいセルの編集に切替 |
| 空セルクリック | 新規エントリを作成して編集開始 |
| アコーディオンヘッダークリック | 編集パネルの展開/折りたたみを切替 |
| モーダル閉じ | 未保存の編集内容を自動保存してからモーダルを閉じる |

**Undo/Redo**:

| 項目 | 説明 |
|------|------|
| カレンダー専用スタック | カレンダーモーダル内の操作用。保存・削除ごとにスナップショットを記録 |
| アコーディオン状態維持 | Undo/Redo実行時、編集アコーディオンが開いていればデータを再読み込みして開いたまま維持。セルが存在しなくなった場合のみ閉じる |
| グローバルUndo連携 | モーダルを閉じる際、セッション中に変更があればカレンダー操作全体を1エントリとしてツールバーのグローバルUndoスタックに追加 |

**機能一覧**:

- [ ] 行単位の月間カレンダー表示（人数バッジ付き）
- [ ] カレンダーセルクリックによるアコーディオン編集
- [ ] セル切替時の自動保存
- [ ] カレンダー専用Undo/Redo（アコーディオン状態維持）
- [ ] グローバルUndoとの連携（セッション単位）
- [ ] 月ナビゲーション（前月/次月切替、セルデータキャッシュ）
- [ ] カレンダー内バッジ表示トグル
- [ ] 単体エントリ削除時の自動保存（アコーディオン折りたたみ＋データ反映）

### 3.3 配置者への追加情報

#### 3.3.1 連絡タイプ管理

配置された社員ごとの連絡方法を管理する。業務管理計画書グリッドで社員名の横にバッジとして表示。

| タイプ | 説明 |
|--------|------|
| 会社 | 会社経由で連絡 |
| 直 | 社員に直接連絡 |
| LINE | LINEで連絡 |
| 迎え | 送迎あり（他社員が迎えに行く） |
| OP | オペレーター経由 |
| その他 | カスタム連絡タイプ（ユーザーが追加可能） |

- [ ] 社員配置時の連絡タイプ選択
- [ ] カスタム連絡タイプの追加
- [ ] グリッド上でのバッジ表示（色分け）

**連絡タイプのカラー管理**:

各連絡タイプにバッジの背景色・文字色・枠線色を定義する。デフォルト5種（会社/直/LINE/迎え/OP）はプリセット色を持つ。カスタム連絡タイプ追加時はカラーパレット（5色）から自動循環で色を割り当てる。色情報はフロントエンドのみで管理し、DBには保存しない。

#### 3.3.2 送迎情報管理

送迎情報は業務管理計画書グリッドの「備考」列に表示する `display_items`（カラータグ）で管理する。

| 項目 | 説明 |

| 送迎関係 | 誰が誰を迎えに行くかの関係を記録（`transport_relations` テーブル） |

※ 移動手段種別（社有車、マイカー等）の個別管理は廃止。必要に応じて備考タグのカスタムアイテムで記録可能

- 全角 → 半角変換
- 半角カナ → 全角カナ変換

- 括弧の統一

**類似度判定:**

| 類似度 | 判定 | アクション |

| 80%以上 | 高類似 | 警告表示、既存候補を提示して確認を求める |
| 50%以上 | 中類似 | 候補リストを表示（参考情報） |
| 50%未満 | 新規 | そのまま登録可能 |

### 3.15 履歴管理

#### 3.15.1 受注変更履歴・ロールバック

**業務背景**: 営業担当者が契約先から受注情報（何日にどの現場で何名必要か）を受け、システムに入力する。
営業担当者が端末を使えない場合は配置担当者に連絡して代理入力する。
別の営業担当者が同じ契約先から誤った伝言を受けて上書きしたり、聞き間違いによる誤キャンセルが発生する。
これらの誤操作から復旧するため、変更履歴の記録とロールバック機能が必要。

| 項目 | 内容 |
|------|------|
| 追跡対象 | 日毎受注（daily_site_orders）の全カラム変更 |
| 記録内容 | 変更カラム名、変更前の値、変更後の値 |
| 変更理由 | 任意入力（例：「契約先からの連絡で人数変更」「キャンセル連絡あり」） |
| ロールバック | 任意の過去バージョンに戻せる |
| ロールバック権限 | 営業担当者・配置担当者・管理者 |
| 競合対策 | 楽観的ロック（バージョン番号照合） + スマートマージ |

**受注ステータス管理**:

| ステータス | 説明                 |
|------------|----------------------|
| active     | 有効（通常状態）     |
| cancelled  | その日のキャンセル   |

**競合解決（スマートマージ）**:

同時編集でバージョン不一致を検知した場合、変更項目の重複有無に応じて解決方法を提示する。

| ケース       | 条件                         | 解決方法                                       |
|--------------|------------------------------|------------------------------------------------|
| A: 非重複    | 自分と他者の変更項目が異なる | 両方の変更をマージして保存（自動マージ候補）   |
| B: 重複あり  | 同じ項目を双方が変更         | 項目ごとにどちらの値を採用するか選択ダイアログ |

- [ ] 受注情報変更時の自動履歴記録（変更カラム・変更前後の値・変更者・日時）
- [ ] 変更理由の入力フォーム（任意）
- [ ] 変更履歴一覧の表示（受注ごと）
- [ ] 任意の過去バージョンへのロールバック機能

- [ ] 楽観的ロックによる同時編集の競合検知
- [ ] 競合時のスマートマージ（非重複項目の自動統合提案）
- [ ] 競合時の手動選択ダイアログ（重複項目の値選択）
- [ ] 受注ステータス管理（active/cancelled）

### 3.16 データベース構造（テーブル相関関係）

本システムのデータベースは、以下の主要なデータグループで構成される。

#### 3.16.1 契約先・現場系

**契約先（companies）** は複数の **現場（sites）** を保有する。各現場は **区分（site_categories）** によって「施設」「イベント」「交通」「高速」などに分類される。

現場は最大3階層の階層構造を持つことができ、**現場子項目（site_sub_items）** で「工事名」「作業内容」などを管理する。例えば「24-1234（PJ番号）→ 〇〇橋補修工事 → 点検作業」のように連結表示される。

#### 3.16.2 社員・資格系

**社員（employees）** は複数の **資格・スキル（employee_licenses）** を保有できる。資格は **資格種別マスタ（license_types）** で「検定」「運転免許」「スキル」の3カテゴリに分類される。

また、人間関係（相性）により同じ現場に配置すべきでない社員の組み合わせを **社員配置制約（employee_conflicts）** で管理する。この制約は配置をブロックするものではなく、警告アイコンで注意喚起を行う。

#### 3.16.3 受注・配置系（中核）

**日毎受注（daily_site_orders）** は営業担当者が契約先から受けた受注情報を管理する。「どの現場に」「いつ」「何名必要か」「時間帯」を記録する。1つの現場に対して昼・夜の2シフトが設定可能。楽観的ロック（version）による同時編集の競合検知に対応。

**日毎配置（daily_assignments）** は配置担当者が管理する配置計画。日毎受注に1:1で紐づき、配置車両（vehicle_ids）を保持する。

**配置詳細（assignment_details）** は日毎配置に紐づき、「誰を」「どの移動手段で」配置するかの詳細を管理する。1つの日毎配置に対して複数の社員を配置できる。

#### 3.16.4 送迎関係

**送迎関係（transport_relations）** は「誰が誰を迎えに行くか」を記録する。運転者と同乗者の関係を日付ごとに管理し、迎え場所も指定できる。

#### 3.16.5 車両・メンテナンス系

**車両（vehicles）** は社有車の情報を管理する。車両は日毎配置（daily_assignments.vehicle_ids）に紐付けられ、1つの現場に複数の車両を配置することも可能。

**メンテナンス予定（maintenance_schedules）** は車検・オイル交換・タイヤ交換などの予定を管理する。Googleカレンダーとの連携も可能。

#### 3.16.6 ペナルティ系

**ペナルティコード（penalty_codes）** は「病欠」「遅刻」などの種別を定義する。**ペナルティ記録（penalty_records）** は社員ごとの発生履歴を記録し、関連する配置との紐付けも可能。

#### 3.16.7 受注変更履歴系

**受注変更履歴（order_change_history）** は日毎受注（daily_site_orders）の全変更を記録する。変更されたカラム名・変更前の値・変更後の値を保持し、任意の過去バージョンへのロールバックを可能にする。楽観的ロック（daily_site_orders.version）により同時編集の競合を検知する。

#### 3.16.8 ログ系

**変更履歴（change_history）** は全テーブルのデータ変更（登録・更新・削除）を自動記録する。変更前後の値をJSON形式で保持。

**通知ログ（notification_logs）** はLINE通知などの送信履歴を記録する。

#### 3.16.9 連続勤務（自動検知）

#### 3.16.10 グループ間請求系

**ユーザー契約先紐付（user_company_assignments）** は営業担当者のアカウントと担当契約先の紐付けを管理する。Quick Access機能で自分の担当契約先を素早く選択するために使用する。

**グループ間請求（intergroup_billings）** は配置完了後に発生するグループ会社間の請求を管理する。受注元のグループ会社と、実際に社員を派遣したグループ会社が異なる場合に自動検知し、経理が確認・処理する。

連続勤務はテーブルで管理せず、配置データから自動的に検知する。「昼→夜」「夜→昼」「昼→夜→昼」「夜→昼→夜」のパターンを検知し、アイコン・バッジと背景色で視覚的に表示する。

#### 3.16.11 休日申請系

**休日申請（employee_day_off_requests）** は社員の休日希望を管理する。社員が紙の申請用紙に記入した希望日を、配置担当者がシステムに入力する。業務管理計画書では、休日申請済みの日は当該社員を配置不可として扱う。

### 3.17 休日申請管理

#### 3.18.10 応援予約行

協力業者への事前交渉で確保した人数を、週間予定表グリッド上で日別・シフト別に管理する行。
各GCに1本ずつ配置され、休み行の上（休み行と通常現場行の間）に挿入される。

| 項目 | 内容 |
|------|------|
| 行ラベル | 「応援予約」（行左端、GC内に1行） |
| 行スタイル | 薄い青/グレー背景（現場行と視覚的に区別） |
| セル内容 | 予約された協力業者バッジ（日別・シフト別） |
| 左端「＋」ボタン | 予約入力モーダルを起動（協力業者の新規登録＋週内日別人数一括入力） |

- 行高さは現場行と同程度を維持する（バッジ内に残数を表示することで行高を抑える）
- **予約0でもセルは空にせず**、`残0` のグレーアウトバッジを表示し続ける（配置・返却操作の頻度が高いため、常に残数を視認できる状態を保つ）

#### 3.18.11 協力業者バッジ（予約行／配置後）

| 表示状態 | フォーマット | 備考 |
|---------|-------------|------|
| 予約行・昼バッジ | `{略称}(昼) 残N` | 昼セルのみにD&D可 |
| 予約行・夜バッジ | `{略称}(夜) 残N` | 夜セルのみにD&D可 |
| 予約行・フレックスバッジ | `{略称}(⇅) 残N` | **昼/夜両セルにクローン表示**、どちらにもD&D可。残数は単一（昼夜共有） |
| 残0状態 | バッジをグレーアウト | D&D不可、ホバーで「残0」を明示 |
| 配置後（現場セル） | `{略称}` のみ | 同一セルに複数配置可（Q3-a） |
| マスタ未完成 | バッジ横に警告アイコン | 注文書発行に必要な正式名称等が未入力の状態（`support_partners.is_master_complete=false`）|

**D&D移動ルール:**

| 移動元→移動先 | 可否 |
|-------------|------|
| 予約行→現場セル | ✅ 可（配置） |
| 現場セル→予約行 | ✅ 可（返却、在庫復元） |
| 現場セル→現場セル（同日内・どの行／昼⇔夜問わず） | ✅ 可 |
| 現場セル→現場セル（別日） | ✅ 可（同シフトのみ、昼→昼／夜→夜） |
| 昼バッジ→夜セル（元がflexでない） | ❌ 不可 |
| フレックスバッジ→昼/夜いずれか | ✅ 可（配置時にシフト確定） |

**×ボタンによる返却:**
現場セル配置済みバッジにホバーで表示される×ボタンでも在庫復元が可能（D&D返却と等価）。

#### 3.18.12 予約入力モーダル

応援予約行の「＋」ボタンから起動し、協力業者の選択＋週内日別人数を一括入力する。

| エリア | 内容 |
|--------|------|
| 協力業者名入力 | 略称をテキスト入力。入力中にオートコンプリート（既存 `support_partners.short_name` から GC一致かつ部分一致で候補表示） |
| 新規登録の場合 | 略称のみ必須。正式名称・住所・代表者等は後から協力業者マスタ画面で補完可（後付け紐付け） |
| 依頼元GC | 選択中のサイドバータブ/GCから自動設定（変更可） |
| 日別人数テーブル | 表示中の週の各日付について、`昼 / 夜 / フレックス` の3列の人数入力欄 |
| バリデーション | 下限0のみ、上限なし（Q36-b） |
| 確定 | 対応する `support_partners` が存在しない場合は新規作成、`support_reservations` に `(partner_id, reserved_date, shift_type)` 単位でUPSERT |

#### 3.18.13 プリセット応援バッジの廃止

従来、各GCに「応援」という名称のプリセット応援バッジが1つずつサイドバーに常駐し、クリック→業者名入力→新バッジ作成というフローだったが、**応援予約行の「＋」ボタンに役割を統一**するため、プリセット応援バッジは廃止する。

- サイドバーから協力業者バッジ棚を撤去
- サイドバーは引き続き社員・車両・現場タブを提供
- 過去モックで実装済みの「プリセット応援＋GC略号表示」（例: `東央｜応援`）は、応援予約行バッジの配置後表示として役割を引き継ぐ

### 3.20 注文書・注文請書発行（新規・将来機能）

#### 3.20.1 概要

協力業者向けの警備業務注文書および注文請書を作成・発行・管理する。
協力業者への発注（応援予約 → 配置 → 注文書発行）の最終ステップとして位置付けられる。

#### 3.20.2 書類構成

| 書類 | 内容 |
|------|------|
| 警備業務注文書 | 甲（委託者＝自社GC）から乙（受託者＝協力業者）に対して業務を注文する書類 |
| 警備業務注文請書 | 乙が甲に対して注文を請ける書類。内容は注文書と同一、甲乙位置を反転、**印紙貼付欄あり** |

#### 3.20.3 三者構造

| 区分 | 役割 | データソース |
|------|------|-------------|
| 甲（委託者） | 業務を委託する側＝自社GC | group_companies（住所・代表者情報含む） |
| 乙（受託者） | 業務を受託する側＝協力業者 | support_partners |
| 丙（発注者） | 業務（現場）の元請＝契約先 | companies（formal_name使用） |

#### 3.20.4 記載項目

| セクション | 項目 | 入力/参照 |
|-----------|------|----------|
| ヘッダ | 発行日 | 入力 |
| 甲 | 住所・会社名・代表者役職・代表者名 | group_companiesから参照＋スナップショット |
| 乙 | 住所・会社名・代表者役職・代表者名 | support_partnersから参照＋スナップショット |
| 丙 | 発注者会社名 | companies.formal_name 参照＋スナップショット |
| 対象 | 対象工事名（現場名） | sites.nameから参照＋スナップショット |
| 対象 | 警備実施場所 | 入力（フリー） |
| 配置 | 配置時間（開始〜終了） | HH:MM形式で入力 |
| 配置 | 配置人数 | 数値入力 |
| 配置 | 検定記載文 | 自動組立（`purchase_order_certifications` から「内◯名以上は◯◯級検定保持者」等の定型組立） or フリー入力 |
| 警備内容 | 警備内容 | フリー入力 |
| 期間 | 実施期間（開始日〜終了日） | 日付入力 |
| 期間 | 期間注記 | 任意（例: 「変更の可能性有り」） |
| 料金 | 日額単価 | 数値入力（税抜） |

| 連絡先 | 発行元会社名・電話 | 甲のGCから自動＋スナップショット |
| その他 | 特記事項 | 定型文マスタから複数選択＋自由追記欄 |

#### 3.20.5 スナップショット方式

注文書発行時、マスタ情報（甲GC／乙協力業者／丙契約先／対象現場名）を `purchase_orders` の `*_snapshot` カラムに保存する。以後のマスタ変更は過去書類に影響しない。

#### 3.20.6 定型文マスタ

- `price_note_templates`: 料金特記欄用（例: 「上記金額は税抜きとなります。」「諸経費を全て含めた金額になります。」）
- `special_note_templates`: その他特記欄用（例: 「警備業法を遵守し、乙の警備員は乙の管理監督の下業務を行う事」）
- いずれもチェックボックスで複数選択、既定ONも設定可、自由追記欄併用

#### 3.20.7 検定種別指定

`license_types` の category='certification' レコードを参照し、`purchase_order_certifications` に必要検定・人数を複数紐付ける。`certification_note` で書類上の表現を組立（自動 or 手動）。

#### 3.20.8 書類ライフサイクル

```
draft（下書き）
  ↓ 発行
issued（発行済：注文書PDF出力、印刷/送付）
  ↓ 受領
accepted（請書受領済：purchase_order_acceptances レコード、印紙貼付確認）
  ↓ 完了
closed（完了：経理処理後）
```

#### 3.20.9 連携

- 週間予定表の応援配置情報（`support_assignments`）から、当該協力業者の対象日・現場を抽出して注文書に反映
- 受注簿・スクリーンレイアウトから、当該日付の発注状況を照会可能に

#### 3.20.10 機能一覧

- [ ] 注文書一覧画面（協力業者別・期間別フィルタ、ステータス表示）
- [ ] 注文書作成画面（対象現場選択＋支援配置引継、三者情報自動補完）

#### 5.1.5.2 過去データから入力（新規追加モーダル専用）

新規追加モーダル（ツールバーの「＋新規追加」ボタン）のRow Informationカード内、昼夜チップの下にアコーディオンで折りたたみ/展開できる「過去データから入力」エリアを設ける。マスターテーブル管理画面が未実装の段階での簡易入力手段として位置づけ、正式な契約先・業務名の管理は今後のマスター管理画面で行う。

| 項目 | 説明 |
|------|------|
| 表示条件 | ツールバーの「＋新規追加」ボタンからの新規追加モーダルでのみ表示。行情報編集・契約先名横の＋・昼夜＋では非表示 |
| アコーディオン | 「▶ 過去データから入力」をクリックで展開/折りたたみ。モーダル表示時は折りたたみ状態 |
| 契約先名バッジ | 会社・区分・昼夜の3項目がすべて選択されると、過去データから該当する契約先名をバッジで表示。既に受注簿に存在する（会社・区分・昼夜・契約先名・業務名）の組み合わせは除外 |
| 業務名バッジ | 契約先名バッジを選択すると、その契約先に関連する業務名バッジを表示（同様に既存組み合わせは除外） |

| 選択状態 | 選択中のバッジはアクティブ状態（アクセント色背景・白文字）で表示 |

## 6. 開発フェーズ

### ■ React + Node.js Webアプリ（先行開発）

#### Phase 1: MVP（最優先）

1. プロジェクトセットアップ（Next.js + Supabase）
2. 認証機能（ログイン・ログアウト）
3. 基本的なマスタ管理（契約先、現場、社員）
4. 受注データ一覧・検索・フィルタ

#### Phase 2: コア機能（業務管理計画書UI）

1. 業務管理計画書のメイン画面（Reactコンポーネント）
2. 日毎配置の登録・編集（ドラッグ&ドロップ配置）
3. 配置者への追加情報（連絡方法、車両・送迎、連続勤務）
4. 受注データ登録・編集・削除

#### Phase 3: リアルタイム同期・通知

1. Supabase Realtimeによるリアルタイム同期
2. リアルタイム変更通知システム（トースト・モーダル・元に戻す/やっぱり反映）
3. アラート・通知（画面内通知 — 連続勤務検知、人数不足、配置制約等）
4. LINE通知連携（LINE Messaging API — 配置確定通知、変更通知の社員向け配信）
5. 入力時あいまい一致バリデーション（表記揺れ検知）

#### Phase 4: 拡張機能

1. 車両管理機能
2. Googleカレンダー連携
3. Excelファイルのインポート・エクスポート機能
4. ペナルティ管理

#### Phase 5: 高度な機能

1. 履歴管理
2. レポート・集計機能
3. 通知の拡張（メール等、LINE以外のチャネル）
4. 詳細な権限管理

### ■ 後続開発

#### Phase 6: 教育記録管理システム

警備業法に基づく備え付け書類を網羅的に管理するシステム。本受注管理システムと連結する。

1. 警備業法に基づく教育記録管理（新任教育・現任教育等）
2. 備え付け書類の電子管理（警備員名簿、護身用具管理等）
3. 教育計画・実績の管理
4. 本システムの社員マスタとの連結

#### Phase 7: 見積書・契約書作成

1. 見積書作成機能（テンプレート管理、PDF出力）
2. 契約書作成機能（テンプレート管理、PDF出力）
3. 受注データとの連携（受注簿から見積書・契約書を生成）
